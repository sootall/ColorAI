# 系統設計說明書（design.md）
**版本**：v0.2｜依據：`requirements.md` F01–F03

## 1. 頁面與功能對照
| 頁面 | 功能 | 畫面元素 |
|---|---|---|
| P01 案例選擇頁 | F01 | 案例卡、虛構案例標記、開始按鈕 |
| P02 交班練習頁 | F01、F02 | 病例摘要、S/B/A/R四個文字框、溝通句欄、儲存／清除／檢核按鈕 |
| P03 回饋頁 | F03 | 空白欄提示、待確認項目、返回修訂按鈕、學習用途提醒 |

## 2. 操作流程
`P01 選案例 → P02 閱讀情境 → 學生自行輸入 SBAR＋溝通句 → 暫存草稿 → P03 規則式檢核 → 回 P02 修訂 → 再次檢核`
- 若案例不存在：提示錯誤並返回 P01。
- 若欄位空白：不阻止儲存，但在檢核頁提示。
- 清除需先確認；不呼叫 AI 補寫未提供的病人資訊。

```text
└──────────────────────┘

```

## 4. 資料結構
- 案例資料：`data/mock_cases.json`，每筆包含 `case_id`、`title`、`scenario`、`facts`、`required_items`。
- 草稿資料（localStorage 鍵名示意）：`handoff-draft:<case_id>`；物件含 `s`,`b`,`a`,`r`,`communication`,`saved_at`。
- `saved_at` 僅為本地草稿紀錄時間；不蒐集學生個資或身份資訊。
- 規則式檢核只用作教學提醒，**關鍵字缺失不等於臨床缺失**。

## 5. 技術方案與原因
- HTML、CSS、JavaScript：初學者易理解，無必須付費的 API。
- localStorage：可在單一瀏覽器中儲存學習草稿，避免額外後端部署。
- JSON：用虛構資料檔建立可重複測試的案例。
- 開發方式：在本機透過簡單的靜態伺服器執行，避免 `file://` 讀取 JSON 的瀏覽器限制；部署方式待小組確認。
- 若開發環境無法穩定載入 JSON：先使用同內容的本地 JS 物件作替代，仍須保留單一資料來源。

## 6. UI 與無障礙
- 色彩：深藍文字搭配淺色背景；對比達可讀標準為目標，須實測。
- 表單標籤完整、按鈕有文字、支援鍵盤操作，錯誤訊息不用顏色單獨表達。
- 案例內容與使用者輸入明確分區，避免學生誤將系統文字視為已確認的病況。

## 7. 設計尚待確認
- 虛構案例必要項目需護理教師核對。
- 護理溝通句不以 AI 主觀情緒分數評價；第一版只提示是否填寫及供教師回饋。
