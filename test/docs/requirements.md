# 需求說明書（requirements.md）
**版本**：v0.2（Gate 2 示範修訂版）｜**狀態**：開發前規劃，尚未實測

## 1. 專題目的與使用者
- **目的**：協助護理學生練習組織模擬病例資訊與清楚、尊重的交班表達；並非代寫真實交班。
- **主要使用者**：護理二、三年級學生；**次要使用者**：護理教師（提供案例與審閱回饋；MVP 不設教師帳號）。
- **情境**：學生於課堂或自習選擇虛構病例，閱讀後自行撰寫交班，依回饋修訂。痛點仍待使用者訪談佐證。

## 2. MVP 功能需求
### F01 選擇模擬病例
- **輸入**：從預先設定的案例清單選一個 `case_id`。
- **處理**：載入對應虛構病例的標題、情境與已提供之事實資訊。
- **輸出**：病例閱讀頁，顯示案例資訊與明確的「虛構案例」標示。
- **驗收**：可切換至少3份案例；頁面內容與資料檔一致；不存在的 `case_id` 顯示錯誤，不編造內容。

### F02 自行撰寫與保存 SBAR 及溝通句
- **輸入**：S（現況）、B（背景）、A（評估資訊）、R（待確認事項）四欄文字，以及一段清楚、尊重的交班語句。
- **處理**：保留學生原文；在同一瀏覽器使用 `localStorage` 依 `case_id` 暫存，允許修改或清除。
- **輸出**：可編輯表單、儲存狀態提示與取回草稿。
- **驗收**：各欄皆可輸入；重新整理頁面後同瀏覽器可讀取；清除按鈕需二次確認，成功後資料消失；切換案例不得讀到其他案例草稿。

### F03 檢核與學習回饋
- **輸入**：F02 各欄文字及預先審閱的案例 `required_items`。
- **處理**：第一版先以**欄位是否空白**及必要項目關鍵字作示範性規則檢核；不可依關鍵字檢核斷言臨床內容正確或同理能力高低。
- **輸出**：列出空白欄位、未偵測到的必要資訊與「請人工核對」提示，學生可返回修訂。
- **驗收**：空白欄位必顯示提示；缺少案例必要資訊時顯示「待人工確認」；不會自動補寫病況；可返回修改後重新檢核。

## 3. 非功能要求與限制
- 手機與桌面瀏覽器均可閱讀；標籤明確，按鈕有文字，高對比、大字與鍵盤操作。
- 不要求登入與網路 API；本機暫存的資料可能被清除，不代表正式備份。
- 只用虛構案例；不能連接醫院系統，不能提供診斷／處置推薦，也不能傳送真實病歷。
- 不開發：語音辨識、即時多人共編、AI 自動生成評分、醫院系統整合、教師管理後台。

## 4. 驗證規劃（非已完成成果）
- **基本功能測試**：三個模擬案例 × 正常輸入、空白欄位、跨案例切換、草稿清除。
- **使用測試計畫**：擬邀請5–8位同學試用，蒐集任務完成時間、必要項目涵蓋率、操作問題與主觀易用性；均尚未收案。
- **專業審查**：請護理教師審閱案例內容及關鍵項目；未審核前不得宣稱專家認證或教學成效。

## 5. 優先順序與需求變更
F01 → F02 → F03。變更需求時更新本文件版本、原因及對應任務；先由小組同意再交 AI 開發。
