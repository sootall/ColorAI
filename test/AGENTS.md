# AI 協作開發規範 — 交班好好說
1. **先閱讀** `README.md`、`docs/requirements.md`、`docs/design.md`、`docs/tasks.md`，以 F01–F03 為準。
2. Gate 2 階段先**檢查規劃，不寫程式**。進入開發後，只執行組員指定的單一任務，不能自行追加雲端 API、登入、語音或病歷串接。
3. 開始修改前：列出任務編號、擬修改檔案、預期輸入輸出、疑問與風險；需求不明先詢問。
4. 完成修改後：列出變動檔案、啟動步驟、手動測試案例、預期與實際結果、尚未通過項目。未實際執行測試，不可宣稱通過。
5. 僅允許 `data/mock_cases.json` 中的虛構資料；不得傳送姓名、學號、真實病歷、密碼或 API Key 到外部服務。
6. 不得編造病例事實或將缺漏解讀為正常；回饋僅作學習提示。不得提供診斷、用藥或處置建議。
7. 採簡單、可供非資訊背景學生理解的程式結構；新增依賴先解釋原因、成本和替代方案。
8. 保留既有檔案及功能；有破壞性更動、刪除資料或跨多檔大量重構時，先取得組員確認。
9. 每完成一個任務提醒組員執行人工驗收與 Git commit，訊息格式如 `T02: add SBAR input form`。
10. 若不同文件有衝突，停止開發，列出衝突及建議選項，由小組決定後更新規格。
